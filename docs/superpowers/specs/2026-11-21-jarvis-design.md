# Дизайн: JARVIS — дневник дня для дочери (PWA)

Дата: 2026-11-21
Статус: на утверждение

## Интент и зачем

Персональный «ДЖАРВИС» для 16-летней дочери — мобильное приложение, которое напоминает вести лёгкий дневник дня и само заполняет таблицу: по фиксированным временным слотам она отмечает, что делала, и оценивает это по двум шкалам (удовольствие 0–10, важность 0–10), плюс общее «настроение дня». Всё копится в историю на её телефоне.

Цель — не контроль, а мягкая привычка рефлексии и ощущение «живого» ассистента в эстетике ДЖАРВИСА.

Кто пользуется: дочь (16 лет). Кто заказывает: родитель. Данные — только у дочери.

## Цели

1. Напоминать заполнять дневник «по кусочкам» (выбранный сценарий A: уведомление после слота → короткий ответ → ДЖАРВИС вписывает).
2. Давать отвечать быстро, без LLM: кнопки быстрого выбора + оценки 0–10 + свободный текст (опционально).
3. Хранить историю локально на телефоне — приватно, без аккаунта и синхронизации.
4. Выглядеть как «голографический синий» ДЖАРВИС: тёмный, голубой градиент, светящееся ядро, минимализм.
5. Работать как PWA: ставится на домашний экран Android, обновляется без переустановки.
6. Давать сохранить историю: кнопка «Выгрузить историю» (JSON/CSV) — скачивание файла локально, без сервера.

## Не-цели (в v1 не делаем)

- Нет LLM-интеллекта (но закладываем «розетку» под него — см. раздел ниже).
- Нет доступа родителя к данным; нет аккаунтов и синхронизации.
- Нет графиков/аналитики и социальных функций.
- Нет публикации в магазине приложений.

## Анти-цели (провал, даже если всё технически работает)

- Не должно ощущаться как «домашка»/обязаловка — иначе дочь бросит.
- Не спамить уведомлениями: настраиваемая частота и «не беспокоить».
- Ни одна запись дневника не должна уходить на сервер без явной необходимости.

## Ограничения

- Телефон: Android (Chrome). PWA, обязателен HTTPS (service worker + уведомления).
- Хостинг: Vercel (бесплатный аккаунт у заказчика уже есть). Деплой выполняет агент.
- Данные: локально в браузере (IndexedDB). На сервере — только push-подписка, настройки расписания и (в будущем) ключи.
- Без серверной части не обойтись: Web Push требует отправки «извне», поэтому нужна маленькая serverless-прослойка и планировщик.
- UI на русском.

## Подходы (рассмотренные и выбор)

| Подход | Плюсы | Минусы | Итог |
|---|---|---|---|
| **PWA (веб-приложение)** | Полный контроль над видом; локальная приватность; лёгкая установка и мгновенные обновления; быстрая итерация | Нужен хостинг + серверная прослойка для push; телефон должен быть в сети для напоминаний | **Выбран** |
| Нативное Android (.apk) | Напоминания надёжны и работают офлайн; ничего хостить не надо | Сложная установка (sideload) и переустановка при каждом изменении; нужен Android SDK | Отклонён |
| Telegram-бот + веб-таблица | Максимально простые напоминания | Убивает «единое приложение в стиле ДЖАРВИС» | Отклонён |

## Как устроено (решения)

### Техстек
- Фронтенд: чистый HTML/CSS/JS (без фреймворков и сборки) + манифест PWA + service worker.
- Хранение: IndexedDB (записи по дням, локально на устройстве).
- Уведомления: Web Push (VAPID).
- Бэкенд: одна-две serverless-функции + планировщик напоминаний:
  - `POST /subscribe` — регистрирует push-подписку устройства (плюс часовой пояс и настройки расписания). Часовой пояс — смещение UTC устройства, обновляется при каждом открытии приложения (пользователь один, стационарно).
  - Планировщик (cron) — в заданные моменты шлёт push-напоминания подписанным устройствам.
  - Секреты (VAPID-ключи, в будущем ключ LLM) — только на сервере, в браузер никогда не отдаются.
- Конкретный механизм планировщика выбирается под бесплатный тариф Vercel (Vercel Cron; если его лимит не даёт частоты «раз в несколько минут» — добавить внешний планировщик, например GitHub Actions). Требование: частота «раз в несколько минут», чтобы время напоминаний было точным; если тариф ограничивает — напоминания приходят с округлением до N минут (допустимо).

### Модель данных (локально, IndexedDB)
- `day { date: "YYYY-MM-DD", mood: 0..10|null, slots: Slot[] }`
- `Slot { start, end, activity: string|null, pleasure: 0..10|null, importance: 0..10|null }`
- Слоты фиксированы (как в исходной таблице): 6–7, 7–8, 8–9, 9–11, 11–13, 13–15, 15–17, 17–18, 18–19, 19–20, 20–21, 21–22, 22–23, 23–6.00.
- День = календарная дата (та, которой подписана строка «Понедельник/Вторник…»). Слот 23–6.00 относится к этой же календарной дате (сон в конце этого дня). «Сегодня» = текущая календарная дата.

### Экраны
1. **Сегодня (главный):** шапка «JARVIS + online», светящееся ядро, переключатель дней (Пн–Вс и листание дат), таблица слотов (Время | Дело | Уд | Важ), строка «Настроение дня».
2. **Ответ на слот** (открывается по тапу уведомления): «Что делала с 6 до 7?» + чипы (Сон, Еда, Сборы, Дорога, Школа, Домашка, Спорт, Прогулка, Хобби, Общение, Отдых, Игры/телефон, Другое) + свободный текст + «Удовольствие 0–10» и «Важность 0–10» (тап по цифрам) + «Сохранить».
3. **История:** листание прошлых дней (пред./след.), просмотр таблиц; здесь же кнопка «Выгрузить историю» (JSON/CSV) — локально, без сервера. Графики/итоги осознанно вне v1.

### Поведение (заполнение и правки)
- Ответ на слот — только тапом по уведомлению (открывается приложение). Быстрых кнопок в шторке уведомлений в v1 нет.
- Любой слот любого дня (включая прошлые и пропущенные) можно заполнить и исправить в любой момент — «Сегодня» и «История» редактируемы.

### Расписание напоминаний (по умолчанию, настраиваемое)
- Напоминание о слоте приходит вскоре после его окончания (+5 мин), кроме:
  - слот 23–6.00 спрашивается утром (~7:00 или при первом открытии после 6:00);
  - «Настроение дня» — один вечерний вопрос (~21:30).
- Тихие часы: 23:00–7:00 без уведомлений.
- Настройки у дочери: отключить отдельные напоминания, режим «одно вечернее напоминание», «не беспокоить». Точная сетка — на строителя; приоритет — не спамить.

### Заготовка под LLM (v2)
- В коде — шов `askJarvis(text)`: в v1 работает локально (просто сохраняет/парсит текст), в v2 ходит на серверный прокси `POST /api/llm` (ключ OpenRouter на сервере, в браузере никогда).
- Бэкенд уже имеет инфраструктуру секретов и планировщика, поэтому подключение LLM = добавить один endpoint и ключ, без переделки фронта.

## Что остаётся строителю
- Точная визуальная полировка в духе «голографического синего» (цвета, свечение, отступы).
- Конкретная сетка напоминаний и поведение для «пропущенных» слотов.
- Настройка хостинга и деплоя, генерация VAPID-ключей, выбор cron-механизма.
- Детали IndexedDB-схемы и service worker.
