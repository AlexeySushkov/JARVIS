# JARVIS — дневник дня (PWA)

Персональный «ДЖАРВИС» для телефона: напоминает вести дневник дня по временным слотам и хранит историю локально на устройстве, в стиле «голографический синий».

## Что умеет

- Суточное напоминание через Web Push (один раз в день вечером).
- Таблица: время / дело / удовольствие (0–10) / важность (0–10) + «настроение дня».
- Поле «Дело» — многострочное: Enter переносит строку, переносы сохраняются в Word-выгрузке.
- История по дням (листание) и кнопка «Сохранить неделю» — выгрузка пн–вс в Word.
- Данные хранятся только на телефоне (IndexedDB), без аккаунта и синхронизации.

## Запуск на ноутбуке (локально)

Нужен установленный **Node.js** (LTS, версия 18+).

```bash
npm install        # один раз — поставить зависимости
node --test        # (необязательно) прогнать тесты
npx serve .        # запустить локальный сервер
# или без npx: python -m http.server
```

Открыть в браузере `http://localhost:3000` (или порт, который показал сервер).

Что работает локально: заполнение таблицы, листание дней, история, «Сохранить неделю».

Что **не** работает локально: push-уведомления — для них нужен деплой на Vercel (HTTPS + сервер + реальный телефон). Тап по уведомлению локально проверить нельзя.

## Деплой на Vercel

**Коротко, как это устроено:**

- **Проект в Vercel создаётся автоматически** — в момент импорта репозитория (это и есть «проект» = приложение + настройки).
- **Проект надо привязать и к хранилищу, и к git**: к git — самим импортом репозитория; к **Upstash Redis** — подключением хранилища к проекту (см. шаг 4).
- **Деплой из git — основной способ**: после первого импорта каждый `git push` в `main` передеплоивает автоматически.

**Шаги:**

1. Войти на [vercel.com](https://vercel.com) → **Add New → Project** → импортировать репозиторий `AlexeySushkov/JARVIS` (Vercel попросит доступ к GitHub — разрешите).
2. Vercel сам определит проект (статический сайт + serverless-функции `api/`), сборка не нужна — просто **Deploy**.
3. Задать **Environment Variables** (**Settings → Environment Variables**). Значения лежат в локальном файле `.env` (в git не попадает):
   - `VAPID_PUBLIC_KEY` — публичный ключ (уже вшит в `app.js`, но продублируйте для сервера);
   - `VAPID_PRIVATE_KEY` — приватный ключ (никому не передавайте);
   - `VAPID_SUBJECT` — `mailto:you@example.com`;
   - `CRON_SECRET` — секрет для cron, защищает `/api/notify`.
4. Подключить **Upstash Redis**: **Project → Storage → Connect Store** → выбрать созданное Upstash Redis. Переменные `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` подтянутся автоматически (код уже использует `@upstash/redis`).
5. Настроить напоминания: они приходят через **штатный cron Vercel** (`vercel.json`: `/api/notify` раз в сутки в 17:00 UTC = 20:00 МСК). Ничего дополнительно настраивать не нужно — Vercel сам передаёт заголовок `Authorization: Bearer <CRON_SECRET>`, если переменная `CRON_SECRET` задана (шаг 3).

**Альтернатива — через CLI:**

```bash
npm i -g vercel
vercel login
vercel deploy --prod
```

## Установка на телефон дочери (Android)

1. Открыть URL приложения в Chrome.
2. Меню → **Добавить на главный экран** (Add to Home Screen).
3. Открыть приложение с иконки и разрешить уведомления.
4. Напоминание приходит раз в сутки вечером; тап по уведомлению открывает поле «настроение дня».

## Уведомления

### Как это устроено (алгоритм)

1. Телефон открывает приложение и разрешает уведомления → браузер создаёт push-подписку (endpoint + ключи) и отправляет её в `POST /api/subscribe`.
2. Подписки хранятся в Upstash Redis (ключ `push:subscriptions`), по одной на каждое устройство/браузер.
3. Cron Vercel (из `vercel.json`) раз в сутки дёргает `GET /api/notify` с заголовком `Authorization: Bearer <CRON_SECRET>`.
4. `/api/notify` читает подписки и шлёт каждой push «Как прошёл день? Заполни дневник.» через Web Push (VAPID).
5. Service worker на телефоне (`sw.js`) принимает push и показывает уведомление; тап открывает поле «настроение дня».

### Расписание напоминаний

Одно напоминание в сутки — cron `0 17 * * *` (17:00 UTC = 20:00 МСК). На бесплатном тарифе Vercel cron может запускаться только раз в сутки, поэтому напоминание одно. Время меняется в `vercel.json`.

### Настройка

- В Vercel (env): `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `CRON_SECRET`.
- Upstash Redis подключён к проекту.
- Расписание — `vercel.json` (`0 17 * * *`). GitHub Actions больше не используется.

### Логи — где смотреть

- **Vercel → Logs** — вызовы `/api/notify` (раз в сутки) и `/api/subscribe`; в ответе `/api/notify` видно `{"sent":[...],"failed":N}`.
- **Vercel → Cron Jobs** — история запусков cron.
- **Upstash → Data Browser** — ключ `push:subscriptions`: список зарегистрированных устройств.

### Проверка

- **Кнопка «Notify»** в шапке открывает настройки уведомлений: статусы «Разрешение» и «Подписка», кнопки **«Включить»** (запросить разрешение и создать подписку) и **«Проверить сейчас»** (тестовый push на это устройство). Проверка работает только на задеплоенном сайте (на `localhost` API нет → `Только на Vercel`). Что означает ответ:
  - `Отправлено ✓` — push передан сервису доставки;
  - `Только на Vercel` — приложение открыто локально (localhost), API-функций там нет;
  - `Нет подписки — нажмите «Включить»` — устройство ещё не подписано;
  - `Не доставлено` — подписка устарела: в Upstash `DEL push:subscriptions` и заново открыть приложение;
  - `Ошибка: <имя>` — полный текст в консоли браузера (F12 → Console).
- **С curl (все устройства):**
  ```bash
  curl -X GET "https://<APP_URL>/api/test-notify" -H "Authorization: Bearer <CRON_SECRET>"
  ```
  Ответ: `{"sent":N,"failed":N,"total":N}`.
- **Сбросить устройства:** в Upstash CLI `DEL push:subscriptions`, затем заново открыть приложение на нужных устройствах.

## Версия приложения

Тап по светящемуся **ядру** в шапке открывает панель «О приложении»:

- **Версия** — `APP_VERSION` из `app.js` (ведётся вручную);
- **Сборка** — короткий хеш коммита и дата, автоматически через `/api/version` (Vercel подставляет `VERCEL_GIT_COMMIT_SHA`, дата берётся из GitHub);
- **Кэш** — имя кэша service worker (`jarvis-vN`), показывающее, свежий ли код у устройства.

При выпуске изменений поднимайте вместе: `APP_VERSION` в `app.js`, `CACHE` в `sw.js` и `app.js?v=N` в `index.html` и `sw.js`.

## Данные и выгрузка

История хранится только в браузере телефона. В шапке — две кнопки:

- **DOC** — скачивает файл `Дневник_JARVIS_<пн>_<вс>.doc`: текущая неделя с понедельника по воскресенье, все 7 дней (включая пустые), каждый день подписан «Понедельник 17.11.2026», таблица «Время / Дело / удовольствие (0-10) / Важность (0-10)» + «Настроение дня». Открывается в Word.
- **Notify** — открывает настройки уведомлений: статус разрешения и подписки, кнопка «Включить» и кнопка «Проверить сейчас» (тестовый push на это устройство).

## Архитектура

- `index.html`, `styles.css`, `app.js` — фронтенд (без фреймворков и сборки).
- `lib/*` — чистая логика (слоты, даты, расписание, хранилище, выгрузка, шов под LLM).
- `api/subscribe.js`, `api/notify.js`, `api/test-notify.js`, `api/version.js` — serverless-функции Vercel (подписки в Upstash Redis, суточное напоминание, тестовый push, версия сборки).
- `sw.js` — service worker (кэш + показ уведомлений).
- `vercel.json` — суточный cron (`0 17 * * *`).
